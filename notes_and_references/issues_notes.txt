General Notes for Issues observed
----------------------------------
- in field_values.yaml for valve_symbols 'D' and 'S' which relate to a manifold base without valve_symbols
the type field is "manifold_base" a submodel or some other class has to be created to handle this other wise it isn't caught correctly

- solenoid_qty is determined from a specific valve_symbols field 'solenoid_qty'. For blanking plates, this is currently set to 0.
However, within component models for valves/blanking plates/ etc a manifold block is generated as double wired when a valve symbol with 
a solenoid_qty of 0 is selected --> blanking_plates. This could lead to an overload of max 32 pins (solenoids) in the case of say 31
single solenoid valves and 1 blanking plate (considered 2 solenoid) = 33.
----> potential fix would be re-allocating valve symbols to blanking plates such that they specify manifold block wiring 

- need to add submodels for EX600 endplates to get part numbers

- need to add submodels for IO units to get part numbers

- need to add supply blocking disk submodel

- add logical condition to main_model to disallow any combinations of valves and empty manifold stations ("D" and "S" options), however make sure 
combinations of "D" and "S" are still possible

- no way to configure mixed fittings with only manifold base and no valves since "D" and "S" are only option without variable fitting_size options

- P/E block is technically two part numbers, in the supply_blocking_disk submodel the part number method just returns one string, 
f"SY{self.series}0M-26-1A , SY{self.series}0M-26-1A" that combines the two part numbers. This should ideally be changed to somehow feature two 
parts that can be grabbed individually
